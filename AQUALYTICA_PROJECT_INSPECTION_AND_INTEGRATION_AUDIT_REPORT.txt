1. EXISTING PROJECT ARCHITECTURE
--------------------------------------------------------------------------------

The current Aqualytica repository is architected as an asynchronous, distributed
multi-tier system with containerized and standalone microservices:

1. Presentation Layer (Port 5200):
   - React.js frontend built with Vite, TailwindCSS, and Framer Motion.
   - Located at: 04_Frontend/water-quality-frontend

2. Middleware Layer (Port 8080):
   - Spring Boot 3.5.x on Java 21.
   - PredictionController: handles /api/predict and /api/telemetry endpoints.
   - PredictionServiceImpl: runs physical sensor anomaly checks and coordinates persistence.
   - PythonMlClient: Spring RestClient communicating with the Flask ML microservice.
   - Esp32StatusService: monitors hardware presence and heartbeat metadata.
   - HikariCP Connection Pool: connection timeout 20s, max lifetime 60s, keepalive 30s.
   - Located at: 03_Backend/springboot-api

3. Machine Learning Layer (Port 5000):
   - Python Flask REST Gateway (app.py).
   - Pre-trained Feature Scaler (Feature_Scaler.pkl - StandardScaler).
   - Pre-trained Random Forest Classifier (Water_Potability_RF_Model.pkl).
   - Hybrid Domain Safety Guardrail Engine (WHO & BIS 10500 drinking standards).
   - Located at: 03_Backend/python-ml-api

4. Data Storage Layer:
   - Supabase Cloud PostgreSQL database.
   - Tables: sensor_data (raw sensor metrics), prediction_history (classification audit), users.

5. Existing Hardware Layer:
   - ESP32 NodeMCU microcontroller.
   - Connected Probes:
     * Analog pH Sensor (GPIO 34 - ADC1)
     * Analog TDS Conductivity Sensor (GPIO 35 - ADC1)
     * Infrared Optical Turbidity Sensor (GPIO 32 - ADC1)
     * DS18B20 1-Wire Digital Temperature Sensor (GPIO 4)
   - Firmware: 05_ESP32/firmware/firmware.ino (currently implements autonomous periodic HTTP POST push).

6. Target Integration Gap:
   - Mosquitto MQTT Broker (Port 1883) for two-way, on-demand command and telemetry communication.

5. ESP32 FIRMWARE INSPECTION
--------------------------------------------------------------------------------

- Location: 05_ESP32/firmware/firmware.ino
- Config Template: 05_ESP32/firmware/config.h.example

- Hardware Pin Assignments:
  * Analog pH Sensor: GPIO 34 (ADC1 Channel 6)
  * TDS Conductivity Sensor: GPIO 35 (ADC1 Channel 7)
  * Infrared Turbidity Sensor: GPIO 32 (ADC1 Channel 4)
  * DS18B20 1-Wire Digital Temperature Bus: GPIO 4

- Digital Filter & Sensor Calibration:
  * readSmoothedADC(pin, 20): Averages 20 analog samples with 10ms delay.
  * Temperature: tempSensors.getTempCByIndex(0); fallback to 25.0 C if disconnected.
  * pH Calibration: voltage = adc * (3.3 / 4095.0); ph = 7.0 + ((1.65 - voltage) / 0.18).
  * TDS Calibration: ecRaw = voltage * 1000.0; ecCompensated = ecRaw / (1.0 + 0.02 * (temp - 25.0));
    tds = ecCompensated * 0.5.
  * Conductivity: conductivity = ecCompensated * 1.5 (uS/cm).
  * Turbidity: turbidity = -1120.4 * (voltage^2) + 5742.3 * voltage - 4352.9; clamp to 0.2 if clear.

- Existing Network & Transmission Protocol:
  * Connects to Wi-Fi via WiFi.begin(WIFI_SSID, WIFI_PASSWORD).
  * Transmits JSON via HTTPClient POST to SERVER_URL (http://192.168.1.100:8080/api/telemetry).
  * Includes HTTP headers: X-Device-ID: ESP32-NODE-01, X-Device-RSSI: <rssi>.
  * Implements offline circular RAM buffer (30 samples) when Wi-Fi drops and flushes to /api/telemetry/batch.

- MQTT Implementation Status:
  * PubSubClient is NOT included.
  * NO MQTT broker configuration exists.
  * NO MQTT publishing is implemented.
  * NO MQTT command subscription is implemented.
  * Operates solely in an autonomous periodic timer loop every 10 seconds.

10. PROPOSED INTEGRATION ARCHITECTURE
--------------------------------------------------------------------------------

Execution Sequence:
1. User clicks "Start Hardware Test" on the React Prediction page.
2. React sends HTTP POST /api/telemetry/trigger-test to Spring Boot.
3. Spring Boot generates a unique UUID requestId (e.g., "REQ-7B9F12").
4. Spring Boot registers a CompletableFuture in an in-memory ConcurrentHashMap<String, CompletableFuture>.
5. Spring Boot publishes an MQTT message to topic "aqualytica/device/command":
   {"command": "START_TEST", "requestId": "REQ-7B9F12"}
6. Mosquitto broker delivers the command to the ESP32.
7. ESP32 parses the command, extracts the requestId, and immediately executes a fresh sensor reading.
8. ESP32 publishes the fresh readings to topic "aqualytica/device/telemetry/response":
   {"requestId": "REQ-7B9F12", "ph": 7.35, "temperature": 23.4, "turbidity": 1.45, "totalDissolvedSolids": 210.0, "conductivity": 420.0}
9. Spring Boot receives the MQTT response, matches the requestId, and completes the pending CompletableFuture.
10. Spring Boot forwards the fresh sensor metrics to PredictionServiceImpl.
11. PredictionServiceImpl runs physical anomaly checks and saves SensorData into PostgreSQL.
12. PredictionServiceImpl queries Python ML API (/predict).
13. Python ML scales features, runs Random Forest model, applies WHO safety checks, and returns classification.
14. PredictionServiceImpl saves PredictionHistory into PostgreSQL.
15. Spring Boot returns HTTP 200 with raw readings, prediction verdict, and confidence to React.
16. React auto-populates the input fields with the physical readings, runs the animation pipeline,
    plays audio chime, and renders the result cards.

Freshness Guarantee:
- Only MQTT messages containing a matching active requestId will complete the pending test future.
- Periodic background telemetry is ignored by the test trigger bridge, ensuring zero stale data contamination.
- If the ESP32 does not respond within 8 seconds, the backend returns a clean HTTP 504 Gateway Timeout.

12. POTENTIAL RISKS AND TECHNICAL ISSUES
--------------------------------------------------------------------------------

1. Sensor Conversion Latency:
   - DS18B20 1-Wire conversion takes up to 750ms; 20-sample analog smoothing takes ~600ms total.
   - Total acquisition time on ESP32 is ~1.5 - 2.0 seconds.
   - Backend timeout must be set to at least 8 - 10 seconds to avoid false timeouts.

2. Spring Boot Rate Limiter Collisions:
   - PredictionController enforces a 1200ms rate limit per IP.
   - Frontend button must be disabled during active testing and for 2 seconds post-completion.

3. ESP32 Wi-Fi / MQTT Drops:
   - Firmware must implement non-blocking auto-reconnect in loop().
   - Firmware should publish LWT (Last Will and Testament) or retained presence flag.

4. Mosquitto Network Bindings:
   - Mosquitto 2.0+ defaults to localhost only.
   - mosquitto.conf must be configured with "listener 1883" and "allow_anonymous true"
     to allow external LAN connections from the ESP32.

5. Stale Periodic Telemetry Interference:
   - Solved via strict requestId correlation. Background periodic packets will never satisfy
     an on-demand test request.
